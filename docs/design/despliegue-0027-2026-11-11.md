## Deuda de despliegue (importante)

El archivo de migración queda **sin seguimiento** en el checkout de la Pi:

```text
?? alembic/versions/20261111_0027_series_anuales.py
```

El código de la app sigue siendo el `main` anterior (modelo sin `SeriesKind`),
pero las columnas nuevas son ignoradas sin problema. Para que el healthcheck
siga viendo `0027`, la imagen actual incluye ese archivo.

Antes de la próxima actualización desde `main`:

- **No actualizar a un `main` que no incluya esta migración** y luego esperar
  que el healthcheck lea `0027` si el archivo no está en el contexto.
- Lo correcto es fusionar la rama `feat/annuales-fase0` (que incluye el archivo
  y el modelo) y desplegar esa versión.
- Si `git merge --ff-only` se queja de que el archivo sin seguimiento sería
  sobrescrito, **no borrar datos**: mover/retirar ese archivo antes del merge y
  dejar que llegue por Git.

## Rollback

La migración es reversible:

```bash
cd /opt/zascarr/zascarr
sudo docker compose run --rm -T zascarr alembic downgrade 0026
```

Si además hubiera que restaurar el backup (no fue necesario; no se movieron
datos): restaurar el dump y recrear el servicio. El backup está en la propia
Pi; no se ha copiado fuera. No se ha ejecutado ningún downgrade ni restauración.
