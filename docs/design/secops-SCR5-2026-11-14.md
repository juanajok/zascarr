## 1. Hallazgos

### 1.1 Menores

#### m-1 — `_url_del_articulo` acepta `:0` (y puerto vacío) pese a exigir 443

`_url_del_articulo` (`services/comicbook_herald.py:88-103`) valida esquema, host y credenciales, pero el
puerto se comprueba con `(partes.port or PUERTO_PERMITIDO) != PUERTO_PERMITIDO` (`:99`). `0` es falsy y
se sustituye por 443, así que `https://www.comicbookherald.com:0/x/` (y `:00`) **pasa** y se devuelve tal
cual; una URL con `:` y puerto vacío también tiene `partes.port is None` y pasa. Sonda propia:
`_url_del_articulo("https://www.comicbookherald.com:0/x/")` → la URL original;
`_url_del_articulo("…:8443/x/")` → `None`. Las pruebas de O1 cubren `:8443`/ápex/http/host ajeno
(`tests/test_comic_book_herald.py:260-274`), pero no `:0`.
**Impacto:** bajo — el enlace del feed solo se pinta/atribuye y el feed configurado lo elige el operador;
no hay SSRF (el host sigue siendo el canónico y no se siguen enlaces externos), pero la allowlist literal
«solo 443» no se cumple en ese borde y un feed configurado con `:0` intentaría una conexión inválida.
**Recomendación:** `if partes.port is not None and partes.port != PUERTO_PERMITIDO: return None` (o
`puerto = partes.port if partes.port is not None else 443`) y añadir `:0`/`:00`/puerto vacío al
parametrizado de rechazo.

### 1.2 Observaciones no bloqueantes

* **o-1 — El tope de 1 MiB se aplica después de descargar.** `novedades` comprueba
  `len(contenido) > MAX_CUERPO` después de que `pedir_con_cache` haya materializado la respuesta
  (`comicbook_herald.py:251-254`); un feed mayor se lee en memoria antes de rechazarse (la caché tiene su
  propio tope de 2 MiB al comprimir, `cache_http.py:62,445-452`). No es una fuga ni un bloqueante; si se
  quiere un tope de transferencia, habría que limitar el cuerpo en la capa HTTP/streaming. La prueba de
  >1 MiB (`tests/test_comic_book_herald.py:210-218`) valida el rechazo lógico.
* **o-2 — `/ui/arcos` pide el feed en el GET cuando la fuente está encendida.** `web/arcos.py:100-114` y
  `:123`; con caché caliente es un hit sin red, pero el primer GET tras 6 h (o sin caché) espera a
  robots/cortesía y hasta el timeout HTTP de 20 s (`comicbook_herald.py:190-197`). Es la observación O2 de
  QA, de rendimiento/UX, no de seguridad; valorar HTMX/lazy o presupuesto menor para esa vista.
* **o-3 — `categorias` no tiene cota explícita.** El título se corta a 500 (`:155-158`) y el cuerpo total
  a 1 MiB, pero `categorias` (`:149-154`) no tiene `MAX_*` propio; hoy no se pinta en la UI. Es la
  observación O3 de QA, sin impacto práctico con el tope de cuerpo.
