# Medición del presupuesto — U13c (#289)

> **Estado:** medición local del presupuesto aprobado. **No es la medición DoD de la Pi** y no declara `PASS` de rendimiento en el entorno de referencia ni de despliegue.
> **SHA del árbol medido:** `a5d45c5bfb81a713cf2cb14fd4c3e2421a343569` (merge de `main` `190bd70` en la rama de #289; incluye #310).
> **Fecha:** 2026-10-23.
> **Presupuesto aprobado:** p95 ≤ 1.500 ms en la primera revisión y p95 ≤ 900 ms en el cambio de página, con fixture de 155 archivos, 20 mediciones en caliente y carga fría aparte. Superar el umbral obliga a optimizar o re-trocear; no se rebaja el número.

## 1. Entorno de esta medición

| Pieza | Valor |
|---|---|
| Máquina | Intel Core i5-8365U, 8 CPU lógicas, 1,60 GHz; 30 GiB de RAM |
| Sistema | Ubuntu 26.04.1 LTS, Linux 7.0.0-38-generic, x86_64 |
| Servidor | `uvicorn` 0.54.0 local, `--lifespan off` |
| Base de datos | PostgreSQL 15.19 en contenedor Docker desechable |
| Python | 3.14.4 |
| Cliente HTTP | `httpx` 0.28.1, keep-alive, sin caché |
| Datos | Biblioteca sintética; sin biblioteca real ni fuentes externas |

Esta máquina **no es una Pi 4/5** ni reproduce su LAN. Los números sirven para comprobar que el presupuesto tiene margen en el código actual y para detectar regresiones locales; no acreditan el DoD.

## 2. Fixture y método

- **155 archivos reales en disco**, en `Comics/Flash 155 (1987)`: 100 en la primera página y 55 en la segunda. Serie local `Flash 155 (1987)`.
- **P1 (primera revisión):** `GET` de la revisión completa, sin marcas ni números editados.
- **P2 (cambio de página):** `POST /revisar` con `HX-Request: true` y el cursor de la página 2; el servicio devuelve las 55 filas de esa página.
- **Calentamiento:** 2 peticiones de calentamiento por escenario.
- **Medición:** 20 peticiones por escenario; se registra p50, p95, mínimo y máximo.
- **Fría:** primera petición de cada escenario después de arrancar `uvicorn`, antes de los calentamientos. Es una fría de proceso, no una fría de caché del sistema operativo.
- La respuesta de la revisión lleva `cache-control: no-store`; el cliente no cachea.

## 3. Resultados (HTTP local)

| Escenario | p50 | p95 | mín. | máx. | Fría |
|---|---:|---:|---:|---:|---:|
| P1 — primera revisión | 52,0 ms | **56,5 ms** | 49,7 ms | 60,4 ms | 408,9 ms |
| P2 — cambio de página | 41,2 ms | **44,3 ms** | 39,3 ms | 45,5 ms | 43,8 ms |

Los dos p95 quedan muy por debajo de 1.500 ms y 900 ms. La fría de P1 (408,9 ms) también queda por debajo del umbral de P1, pero no se usa para declarar el DoD.

### Contraste en proceso (ASGI)

La misma medición en proceso, sin el viaje HTTP, dio:

| Escenario | p50 | p95 | Fría |
|---|---:|---:|---:|
| P1 — primera revisión | 48,2 ms | 50,9 ms | 259,2 ms |
| P2 — cambio de página | 44,5 ms | 49,2 ms | 61,9 ms |

La diferencia es la esperable por el servidor y el tamaño de la respuesta (la primera revisión entrega la página completa; el cambio entrega el fragmento). Ambas ejecuciones apuntan al mismo margen.

## 4. Lectura y límites

- **Margen local:** el código actual no se acerca al presupuesto en esta máquina. No hay señales de que haga falta optimizar o re-trocear por rendimiento.
- **No es un `PASS` de referencia:** faltan la Pi 4/5, su LAN y el navegador de referencia. La medición en la Pi sigue **NOT RUN** y requiere autorización separada; no se ha tocado la Pi.
- No se ha usado la biblioteca real ni staging. El fixture es sintético y los archivos son reales en disco.
- El resultado no cambia el presupuesto ni autoriza a rebajar los umbrales. Si la medición en la Pi superara 1.500/900 ms, el siguiente paso sería optimizar o re-trocear.

## 5. Reproducción

La medición se hizo con un banco local sobre el árbol del SHA indicado: base de pruebas desechable, 155 archivos sintéticos, `uvicorn` local y 2 + 20 peticiones por escenario. El banco y la siembra fueron herramientas locales de esta medición; la evidencia persistente es esta ficha con el entorno, el fixture, el método y los resultados. Para repetirla en la Pi hay que usar el protocolo del contraste (`u13c-contraste-dor-289.md` §6.4) y registrar hardware, BD, red, navegador, SHA y herramienta.
